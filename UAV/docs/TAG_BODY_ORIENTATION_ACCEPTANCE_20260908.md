# 大小 Tag 机体系姿态接入与静态校验

2026-09-08 已部署。粉色箭头不再在 JavaScript 中计算 45° 补偿：它使用树莓派返回的机体系姿态重新投影到图像的端点。

## 坐标与链路

- 相机光学坐标：X 画面右，Y 画面下，Z 沿光轴。
- 机体 BODY_FRD：X 前，Y 右，Z 下。
- 统一降落板坐标：X 大 Tag 印刷图案上方，Y 图案右方，Z 穿入板面。
- 使用与降落桥和 IBVS 相同的 `moving_landing.prototype.json` 外参；两处旋转不一致时不输出有效方向。
- 当前旋转为 `[[0,-1,0],[1,0,0],[0,0,1]]`，即前=-相机Y、右=相机X、下=相机Z，与 9 月 8 日人工确认的安装轴向一致。
- PnP 的既有角点配对为 TR、TL、BL、BR，对象轴 X 指图案左、Y 指图案上。内层按纸面 CCW 45° 布局补偿到统一板坐标，再变换到 BODY_FRD。使用迭代 PnP 解算方向并检查重投影误差；保留原 IPPE 平移和距离修正。
- API 每个检测结果的 `orientation` 提供原始小 Tag 上方向、统一板前向、BODY_FRD 旋转矩阵、wxyz 四元数、机头相对方向角，以及由 BODY_FRD 回投影的箭头端点。
- 降落桥校验姿态来源、旋转与控制外参一致性及四元数一致性，将 `orientation_body_frd_wxyz` 写入观测，并用于 `LANDING_TARGET.q`。已有 MAVROS 转换负责还原线上 BODY_FRD 四元数。旧版纯位置输入仍保留原有兼容行为。
- 方向角 0° 为机头，+90° 为机体右侧。这次接入的是目标姿态数据，没有开启偏航控制；现有 ArduPilot 精降后端仍主要使用位置/视线数据。

## 验证结果

树莓派 venv 中的隔离测试未打开摄像头或发送消息：20 组带畸变的合成检测覆盖大小 Tag、五个方向和两种倾斜姿态，验证 PnP → 统一板 → BODY_FRD → LANDING_TARGET → MAVROS 四元数往返，以及外参不一致与姿态损坏的拒绝。网页测试验证无后端姿态时不再回退到 UI 自行计算。

用户先确认标签板朝机头摆放，再靠近摄像头。北京时间约 12:50 的连续 40 组实物数据：

| 数据 | 大 Tag ID 0 | 小 Tag ID 1（补偿后） |
|---|---:|---:|
| 有效样本数 | 40 | 40 |
| 平均机体系方向角 | -1.33° | -1.39° |
| 样本方向角范围 | -2.25° ～ -0.34° | -4.26° ～ +0.35° |
| 平均前向单位向量，前/右/下 | [0.991,-0.023,-0.130] | [0.979,-0.024,-0.125] |

40 组配对中，小 Tag 与大 Tag 的方向角平均差为 -0.062°。两者均接近机头方向。采样期间始终未解锁。实时降落桥状态收到 `accepted_this_poll=true`、`ACCEPTED_PACKET_READY`、`stream_healthy=true`。

本次是朝前摆放的静态校验；没有进行实飞、自动偏航验收或重新测量完整安装外参。

## 部署与回滚

新增视觉辅助模块为 `ov9281_debug/ov9281_tag_orientation.py`。视觉服务、降落桥和模型共享同一姿态契约；原执行器、下降控制和控制参数保持独立。部署前必须确认未解锁、`ON_GROUND`，并保留可验证的上一版文件以便回滚。
