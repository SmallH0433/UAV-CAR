This restores the noon yaw-first landing behavior and removes subsequent afternoon/evening landing, vertical-monitor, and vision endpoint changes. Logs and recovery archives remain outside the published source tree. Existing Git history is preserved by a new rollback commit.

The companion parameter file is a **manual archive**, with no automatic loading:

- 24 accelerometer, gyro and attitude-trim values restored from the full backup taken immediately before the evening six-face calibration.
- The pre-calibration learned hover thrust restored.
- `LAND_SPD_MS=0.5` and `PLND_RET_MAX=4` restored from the direct readback made before the afternoon change.
- Vehicle identity, automatic barometric references, storage startup state and flight/runtime counters are not overwritten.

All 27 values passed per-parameter independent reads, a final full-group read, and a separate complete 1015-parameter USB readback. The firmware image was not changed. Startup gyro calibration remains enabled; its eight bias/temperature values may be recomputed normally on reboot. Parameter persistence across a reboot is pending verification.

Validation: all 115 focused checks passed (96 landing-baseline, 5 recorder and 14 sensor-range bridge checks), as did 72 Python syntax checks. The parameter restoration tool passed 13 offline protocol/guard tests; the device file transaction passed six offline failure-path scenarios. Those two failures are also present in the authoritative noon candidate, so the restored runtime bytes were not changed to satisfy stale expectations. This is restoration evidence, not a new flight acceptance test.
